# 推广大使

## 管理员操作

1. 让推广大使先注册并验证网站账户。
2. 在 `/admin?view=users` 搜索她的账户，打开详情，点击「为此用户开通推广大使」。
3. 填写显示名称和 3—32 位专属代号（英文小写字母、数字、短横线），开通后复制 `https://站点域名/r/代号`。代号和账户固定，避免已发链接和归属改变。
4. 在「推广大使」查看累计注册、期间新增、充值人数、成功订单、成功充值金额、退款金额和 Apple 正式记录。可按北京时间日期筛选，导出 CSV 核对表，进入每位大使的用户、订单、总览。
5. 暂停大使会同时关闭其链接和后台访问；历史用户归属、后续充值统计保留。可以重新启用。

大使使用自己的账户登录 `/admin`，个人中心也提供后台入口。沿用原有总览、用户、手记、评论、交易、举报页面，只能查看名下数据，不能赠送会员、修改内容或处理举报，也不能管理其他大使或发布网站内容。管理员仍可读取和管理全站数据。

## 归属和统计口径

- 首次有效推广链接产生服务器保存的随机凭证，浏览器以 HttpOnly、SameSite=Lax Cookie 保留 30 天。重复点击不会延长有效期；凭证对应的大使暂停或凭证过期后可重新接受其他有效链接。
- 网站邮箱注册（含自建邮件验证码和 Supabase 邮件）、微信网页授权和微信小程序中转注册都传递凭证。在 Auth 创建账户的同一事务中记录归属。验证码未完成的 Auth 账户也计入注册数，与现有后台口径一致。
- 已有账户登录、重新申请验证码、修改用户资料、绑定微信不会改变归属。不回填历史来源。清除 Cookie、换浏览器或从浏览器转到独立原生 App 注册不能自动传递来源；应先通过链接在网站完成注册，再使用同一账户登录 App。后续充值无论从哪个端发起，均按账户归属统计。
- 同一账户只能属于一位大使，归属表只允许触发器写入，普通客户端和应用服务端均没有直接增删改权限。后台大使角色来自服务器持有的独立表，不能通过用户资料伪造。
- 充值人数跨支付宝、微信按账户去重；金额使用整数分，只包含 `status=paid` 且 `credited_at` 已存在的订单。待支付、已关闭、已退款及尚未入账的订单不计入成功充值。
- 日期按原订单支付时间筛选，包含首尾日期，北京时间，结束条件为次日零点。退款单独统计并归入原支付日期，不是退款发生日期。现有支付数据未保证退款平台状态完全同步，线下结算前仍需核对支付平台。
- Apple 仅计正式环境记录数量，不计入充值人数或金额。现有数据库未保存 Apple 实付金额，也未完整记录退款；不通过标价猜测金额。
- 汇总仅供线下返利核对，不自动算比例、打款或记作已结算。导出以当前筛选为准。

## 实现与发布

已在当前 Supabase 项目应用两项新增迁移：

- `20260928044031_ambassador_referrals.sql`
- `20260928045115_harden_ambassador_service_grants.sql`

新表和视图均禁止匿名及普通登录客户端访问。分大使读取通过服务端身份验证后，使用带归属编号的 SQL 视图，在统计和分页前筛选。API 每次重新核对大使状态；所有写接口仍仅允许原有管理员。Auth 注册触发器位于非公开 `private` schema，以固定空 search_path 执行，撤销所有客户端的函数执行权限；此处需要 SECURITY DEFINER 才能在 Auth 创建账户时写入仅服务器可见的归属表，其余报表函数和视图使用 SECURITY INVOKER。

生产 `NEXT_PUBLIC_SITE_URL` 应使用网站规范的 HTTPS 域名，用于生成分享链接及安全 Cookie。推广大使代码已随 2026-09-28 的阿里云部署上线，后台接口的未登录访问已验证为拒绝。

安全检查器提示新增三张表「RLS 已开启但无策略」是刻意禁止浏览器直接访问，并且已经撤销客户端授权，不应添加公开策略。解释见 [Supabase 权限检查文档](https://supabase.com/docs/guides/database/database-linter?lint=0008_rls_enabled_no_policy)。其余检查器告警来自原有对象，本次没有修改。

## 微信注册归属修复（2026-09-28）

GoTrue 的 Admin createUser 先插入账户，再更新 app_metadata；仅把推广 token 放入 app_metadata 会错过 AFTER INSERT 归属触发器。微信创建账户现与邮箱注册一致，在首次插入的 user_metadata 中也携带经过服务端校验的 token，app_metadata 继续保留原始来源。未增加 UPDATE 归属触发器，旧账户登录或修改资料不能补领、更改推广归属，后台权限仍来自服务端身份表。

通过真实 Auth API 验证：修复前微信新账户漏记；修复后微信新注册、重复登录、跨应用 unionid 账户复用、旧账户排除、邮箱 generateLink 注册以及汇总查询均通过。测试不会发送邮件或创建支付订单，临时账户与访问记录自动删除。手动执行：`AMBASSADOR_TEST_CODE=<启用的大使代号> node --import tsx scripts/check-wechat-referral.ts`。此测试会短暂影响该大使的注册数，勿放入自动构建。

已漏记的记录使用 `supabase/repairs/backfill_wechat_signup_referrals.sql` 核验补回：必须同时有服务端注册元数据、注册前已创建的授权 ticket、有效访问记录；保留真实注册时间，不覆盖已有归属，不将老账户再次登录计作新增。该文件是受控数据修复脚本，不修改数据库结构或权限。
