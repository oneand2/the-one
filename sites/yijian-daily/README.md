# 《见天地》每日编刊

刊期保存在项目的 Supabase：每个日期对应 `jtd_news_editions` 的一条记录，包含整期稿件、来源、图注和封面；原图单独存入私有的 `jtd-news-photos`。网站共用一套版式。日常出刊不生成本地稿库、图片目录、全站新闻脚本或离线网页。

日刊按北京时间每天 08:00 截稿并开始编刊，以截稿日为刊期。纳入前一日 08:00（含）至当日 08:00（不含）首次公开的新闻或已有报道的实质进展。校验稿件和配图后签发。补跑沿用原定窗口。

## 头版、选读讲清前因后果；短讯保持简短

给第一次听说这件事的人写。标题点明当天发生的变化。选取足以解释这次变化的前情，写清谁在什么情况下采取了什么行动，事情因此走到哪一步，对谁已有实际影响。决定性的事实应放在导语或正文前部；年份、履历和行业常识只有在能解释这次转折时才值得写。

判断一段背景该不该留，可以问：删去它，读者会不会误解当事人为何在这一天作出决定？例如报道企业换帅，若董事会从公开支持当事人转为讨论撤换，应交代其间披露了什么，以及谁证实了什么。涉及个人关系，写明与公共职务、利益冲突或调查有关的事实，并注明出处。把当事人的承认、媒体引述的指控、当事方的回应和正式调查结论分别归属到来源；公开证据只支持时间先后时，就写时间先后。尚无定论的直接原因如实交代。

具体内容随选题取舍。模型发布稿应交代此前用户怎样完成同一件事、新模型改变哪一步、谁已能使用；政策稿应说明原有规定、此次改了哪条、从何时起影响哪些人；财报和股市稿应区分经营变化、盘面表现和对涨跌原因的解释。展览与国际事件同样要给出理解当天新闻所需的历史或现实背景。用可查证的事实说明长远影响成立的条件，预测注明提出者。

以上前因后果要求适用于头版和选读，篇幅由材料决定。发稿前逐篇从头读一遍：读者能否说出「此前怎样、这次为何有变化、现在影响谁」？若关键一环缺失，回查截至该刊截稿时的原始材料或可靠采访，把支持关键转折的原文加入 `sources`。往期链接供延伸阅读，本篇自行交代必要前情。

短讯只写简短的核心事实：一般一段、1–3 句，交代谁在何时做了什么及最关键的结果或数字即可。不要求说明前因后果，不补行业常识、历史背景或长远影响来凑完整叙事。保留避免误解所必需的限定（例如「原则协议」「拟议」「尚未生效」），来源、截稿窗口和图片核验标准照常执行。新增、修订已刊短讯及每日自动编刊均遵守此规则。

## 新增或更正一期

从项目根目录运行。编刊端将一期 JSON 直接传入命令的标准输入；`--date` 指定刊期，`photo.src` 填新闻配图本身的 HTTPS 直链。稿件和图片在进程内处理，不需要先保存到电脑。只有在一次性迁移已存在的本地稿件时需要 `--file` 和 `--assets-dir`。

```sh
# 从上游编刊程序接收 JSON；示例日期可替换。
# 先运行 --dry-run 预检，去掉该选项会写入云端草稿；加 --publish 则签发。
node scripts/publish-news-edition.mjs --date 2026-11-14 --dry-run
node scripts/publish-news-edition.mjs --date 2026-11-14 --publish
```

需要查看空白稿件结构时，运行 `python3 sites/yijian-daily/edition.py new YYYY-MM-DD`（以实际日期替换）；模板只打印到标准输出。不要把模板当作成稿提交。

发布器校验来源、配图大小和像素、往期链接，先上传并回读所有配图，再写入整期正文。重复提交相同内容不会新增刊期。用 `node scripts/publish-news-edition.mjs --read --date YYYY-MM-DD` 读取可编稿的云端版本（版本号输出到 stderr）；核对稿件后加 `--expect-revision N`；也可直接使用云端现稿中的图片地址。用 `--verify-only --publish` 可对照输入核验已刊全稿和原图。令牌仅在服务端读取，不得写入稿件、网页、浏览器或 Git。此处的“签发”只表示读报服务可取这期；它不改变网站的访问权限。

## 稿件字段

| 字段 | 填写方式 |
| --- | --- |
| `id`, `placement` | 使用稳定的小写英文、数字、连字符作为同日唯一标识。`lead` 为头版，`selected` 为选读，`brief` 为短讯。 |
| `category`, `section`, `city` | `category` 填「国际」「科技」「金融」「民生」或「艺术」。`section` 填报道主题，`city` 填事件地点，例如「AI 模型」「北京」。 |
| `title`, `deck`, `paragraphs` | 标题交代发生了什么，导语提炼影响，正文按段填写。短讯的首段也用于头版摘要。可以用可选的 `coverPhrases` 指定标题适合断行的词组。 |
| `sources` | 数组，每项为 `["来源名称", "原文链接"]`。 |
| `photo` | `src` 填原图的 HTTPS 直链（需返回 JPG、PNG 或 WebP 图片），`width`、`height` 填原图像素。`alt` 描述画面，`caption` 交代场景及拍摄时间，`label` 区分现场图、资料照或发布画面。`credit` 和 `sourceUrl` 记录作者或机构及原出处。需要标注许可时，一并填入 `license` 和 `licenseUrl`。 |
| `previousStory` | 可选。填入 `YYYY-MM-DD/往期报道id`，内页会提供前情入口。 |

刊期可另填 `description` 作为页面描述，默认使用头版标题。当日选题优先核实新 AI 模型、上市公司和股市的重要变化。每条核对事件日期、原始消息和图片出处，资料图片注明拍摄时间。

## 预览与归档

项目根目录运行 `npm run dev`，在本机打开 `/news/index.html`。用日期菜单切换期次；固定链接采用 `?date=YYYY-MM-DD#front` 或 `?date=YYYY-MM-DD#article/报道id`。阅读器通过主站服务端获取所选刊期和配图，不能只用静态文件服务器预览。日常出刊不用重建站点，也不导出离线 HTML。

这个栏目与旧的 `world_news` 新闻列表是两套数据。管理云端档案时使用 Supabase 的 Table Editor（`jtd_news_editions`）和 Storage（`jtd-news-photos`）。更改签发状态和修订正文应通过上述出刊流程。

最初交付的三份离线版（2026-11-11 至 2026-11-13）另存于私有桶 `jtd-news-legacy`，按日期建目录，文件名是原件的 SHA-256。要恢复当时交付的完整网页，在 Storage 中下载对应日期的 HTML 即可。此目录只存历史原件，不随每日出刊扩充。
